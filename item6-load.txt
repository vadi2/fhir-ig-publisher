Title: Watch: start rebuilds faster (SUSHI alongside the start-up, kept rapido state, one package cache manager)

Builds on #1447 (perf/rapido-dependencies).

In `-rapido -watch`, every rebuild after an FSH edit first runs SUSHI, and only then starts the publisher's start-up (template, IG resource, package cache, rapido state). On uz.dhp.core that is about 4 s of SUSHI followed by several seconds of start-up work that doesn't need SUSHI's output, plus work that is the same in every build of a session.

### Cause

- The start-up waits for SUSHI, though most of it (template, IG parameters, package cache, tx cache) doesn't read fsh-generated.
- Each build reads and parses the rapido `state.json` that the previous build of the same JVM has just written.
- Each build makes a new package cache manager, which fetches the CI build list again, and checks each `#current` template against the server again.

### Fix

- **SUSHI alongside:** once SUSHI has run in the session, a rebuild starts SUSHI on a thread when the template's onLoad has run, and the start-up goes on. The start-up doesn't read fsh-generated until SUSHI is done: the IG resource is read before SUSHI starts, the template's pre-process folders and the resource/page folder checks wait for SUSHI, and if an IG parameter names a file in fsh-generated the start-up waits for SUSHI at once. If SUSHI changed the IG resource, the start-up is done again on new fields (SUSHI isn't run again). SUSHI's log lines are logged when the start-up waits for it; its failure is the build's, with a start-up failure kept as suppressed. Not used for the first build, after a failed SUSHI, with a `module`, or without an `ig` in ig.ini.
- **Rapido state:** the state a watch build saves is kept in memory and handed to the next build, once, if `state.json` is still the same file (name, size, modified time, file key); otherwise the file is read.
- **Package cache manager:** one per watch session (a new one after a failed build, so a failed CI list fetch is retried); `#current` templates are checked against the server once an hour in a session instead of every build.
- Builds without `-watch` are unchanged, apart from the folder checks running after the template translations instead of before them.
