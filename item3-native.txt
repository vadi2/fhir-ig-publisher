Title: Generate native outputs on the -threads workers
Branch: vadi2/fhir-ig-publisher perf/native-outputs-threads, base HL7 master 42687809, commits 5fda240b ab00247b 3d2f21c4

With `-threads`, the "Generate Native Outputs" step still runs on one thread. For every file in the change list it writes the JSON, XML and Turtle of each resource, once per language, plus the `_includes` copies, while the workers sit idle. On uz.dhp.core (811 files) that takes about 12 s of a complete build.

### Cause

- `PublisherGenerator.generate()` loops over `pf.changeList` and calls `saveNativeResourceOutputs()` for each resource in turn. Most of that work is per resource and touches nothing shared; only the package entries, the cross-version notes and the database row are shared.

### Fix

- With `-threads N` (N > 0), the files are done on N workers by a new `OrderedWorkers`, which hands each file's result back to the main thread in change-list order, at most 8N files ahead. With `-threads 0`, the default, the loop is as before.
- The workers write the files into temp. Everything that adds to shared state - the npm, per-language and per-version package entries, the cross-version omissions and problems, the "Unable to convert" line, the debug log - is kept as a step and run on the main thread, in the same order as without threads, so the packages come out the same.
- The database rows are saved last, in order, once no worker is left. Saving a row marks the resource (and a custom resource's StructureDefinition) with its key, which the workers read.
- Failures behave as without threads: the steps and rows of the resources before the failing one still run, and the same exception is thrown, Errors included. The workers are waited for, even when the build is interrupted.
- If two resources' type and id differ only in case, they would write the same file on a case-insensitive file system, so then the files are done without threads.
- Two counters that the workers now update together are made thread-safe: the Rapido template fragment counts and `FetchedFile`'s shared column list.

Adds `OrderedWorkersTest` (10 tests), `NativeOutputsThreadsTest` (6), `TemplateFragmentCountTest` and `FetchedFileColumnsTest`: the package entries, notes, rows, files written and output names match the run without threads on 1, 3 and 8 threads, covering logical-as-Binary, custom resources, ADL, conversion failures, no database, exceptions and Errors; all mutation-checked.

Checked on uz.dhp.core: the complete builds of master and this PR write the same 20,643 files. Apart from the build dates, they differ only where two builds of the same jar differ from each other. That includes the order of the "used by" links in codesystem-list, codesystem-ref-list and codesystem-ref-all-list (.json and .csv): they come from a HashSet of resources, so their order follows identity hash codes and changes between runs of either jar; the entries are the same. The QA counts are the same (0 errors, 262 warnings, 8,521 hints, 6 broken links in the complete builds).
