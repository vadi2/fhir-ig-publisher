WHAT AND WHY
In `-rapido -watch`, a profile/instance (FSH) edit gives a complete build, and #1461's kept Jekyll and html check replay
don't apply to it. Jekyll renders the whole site, the html checks go through all ~20 700 output files, and the AI step
writes all its files. On uz.dhp.core that tail is >100 s of a 170-180 s rebuild, whatever the edit.
Causes and fixes:
(a) Every build stamps a new time (genDate in _data/fhir.json, canonical resources without date, page footers), so every
    page/temp file changes. Fix: in -watch, every build of the day is dated at the day's first build (WatchSession pins
    execTime/genDate; new day = new time). qa.txt/qa.json still carry the real run time (pf.setReportTime).
(c) Html check records were keyed by object identity (context/specs/sources = new objects each complete build). Fix:
    records carried to the next complete build and compared by content signature (HTMLInspector.recordSignature,
    SpecMapManager.contentSignature: specs, linked specs, related IGs, sources, settings). Unreadable related IG gives
    a unique "unknown <uuid>" signature (never matches) and is logged. If Jekyll can't write again a file a carried
    record needs, HTMLInspector.OutputRewriteFailure (extends IOException) makes Publisher.completeBuild retry without
    carried state (PageRebuild.dropped() -> carryOver returns empty state).
(b) A complete build asked the kept Jekyll for a full `build` and cleared the staged output. Fix: staged output
    (pf.outputDir = tempDir/.watch-output) kept; PublisherIGLoader.clearOutputUnlessKept() only deletes staged qa.json
    and package.tgz; JekyllDriver tracks the temp sources it read (SHA-1, reused while stamp size:ino:ctime is the same),
    and PublisherGenerator.changedSources asks Jekyll to `update` only the changed ones. New/removed/_data files fall back
    to a full Jekyll build in the Ruby side. Full build (with log line "Rapido Mode: Jekyll renders the whole site
    (<reason>)") when: template's whyOnCheckMaySeeOutput != null, staged output not kept, no kept state, html checks
    not reusable, or what Jekyll last read is unknown (restarted/failed/stopped). A source scan failure logs and clears
    tracking (JekyllDriver.rescan) instead of failing Jekyll.
    The package.tgz delete matters: genCombinedPackage runs before package.tgz is written (pre-existing upstream bug, it
    always errors in normal builds); with staging kept it found the stale package.tgz and spent +17-19 s.
(d) Jekyll's Cleaner removes non-site files, so the AI step rewrote all of them. Fix: AIProcessor.Cache.keepOutputs moves
    them to temp/.ai-outputs while Jekyll runs, putBackOutputs puts them back, only markdown/zips whose content changed are
    written, files no longer made are removed (removeUnmade, failed deletes logged). keepAiOutputs skipped when the
    template check may see output, catches IOException|RuntimeException. .ai-outputs, _rapido, full-ig.zip are untracked.
Builds without -watch: unchanged (the new paths are all gated on watch state).

snap.py:
    #!/usr/bin/env python3
    """snap.py <dir> <out.tsv> [skip-subdir ...]: per file: relpath, size, sha1(raw), sha1(masked)
    masked = the build's genDate/genDay strings (read from <temp>/_data/fhir.json if found next to dir, or env GENDATES
    '|'-separated) replaced, plus UUIDs and ISO dateTimes with time part."""
    import hashlib, json, os, re, sys
    root, out = sys.argv[1], sys.argv[2]
    skip = set(sys.argv[3:])
    gens = [g for g in os.environ.get('GENDATES', '').split('|') if g]
    for cand in [os.path.join(root, '_data', 'fhir.json'), os.path.join(root, '..', '_data', 'fhir.json'),
                 os.path.join(root, 'pages', '_data', 'fhir.json'), os.path.join(root, '..', 'temp', 'pages', '_data', 'fhir.json')]:
        if os.path.exists(cand):
            try:
                d = json.load(open(cand, encoding='utf-8'))
                gens += [d.get('genDate', ''), d.get('genDay', '')]
                try:
                    import datetime
                    t = datetime.datetime.strptime(d.get('genDate', ''), '%a, %b %d, %Y %H:%M%z')
                    gens.append(t.strftime('%Y-%m-%d %H:%M:%S %z'))
                except Exception:
                    pass
                break
            except Exception:
                pass
    gens = [g.encode() for g in gens if g]
    UUID = re.compile(rb'[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}')
    ISO = re.compile(rb'\d{4}-\d\d-\d\dT\d\d:\d\d(:\d\d(\.\d+)?)?([+-]\d\d:\d\d|Z)?')
    with open(out, 'w') as o:
        for dp, dn, fn in os.walk(root):
            rel = os.path.relpath(dp, root)
            dn[:] = [d for d in dn if os.path.normpath(os.path.join(rel, d)) not in skip]
            for f in fn:
                p = os.path.join(dp, f)
                try:
                    b = open(p, 'rb').read()
                except Exception:
                    continue
                raw = hashlib.sha1(b).hexdigest()
                m = b
                for g in gens:
                    m = m.replace(g, b'@GEN@')
                m = ISO.sub(b'@ISO@', UUID.sub(b'@UUID@', m))
                o.write(f"{os.path.normpath(os.path.join(rel, f))}\t{len(b)}\t{raw}\t{hashlib.sha1(m).hexdigest()}\n")

Branch: vadi2/perf/watch-fsh-tail (not pushed). Builds on #1461.

Title: Watch mode: FSH edits reuse the kept Jekyll, the html checks and the AI step

In `-rapido -watch`, a profile or instance edit gives a complete build, and #1461's kept Jekyll and html check replay don't apply to it. Jekyll renders the whole site again, the html checks go through every output file, and the AI step writes all its files. On uz.dhp.core that tail takes over 100 s of a 150-175 s rebuild, whatever the edit.

### Cause

- A complete build asks the kept Jekyll for a full `build`, and clears the staged output it could go on from.
- Every build stamps a new time into `_data/fhir.json` (genDate), the canonical resources without a date and the page footers, so every page and most temp files change.
- The html check records are keyed by object identity (context, specs, sources), which are new objects in every complete build.
- Jekyll's cleaner removes the AI step's files, so the AI step writes them all again.

### Fix

- **Build time:** in `-watch`, every build of the day is dated at the day's first build; a new day gets a new time. qa.txt and qa.json still say when the build ran.
- **Kept Jekyll:** a complete build keeps the staged output, and asks Jekyll to update only what depends on the temp files whose content changed (SHA-1, reused while the file's stamp is the same). New, removed or `_data` files, a stopped or failed Jekyll, or a template check that may look at the output give a full Jekyll build, with a log line that says why.
- **Html checks:** the records are carried to the next complete build, and compared by what the check looks up (specs, linked specs, related IGs, sources, settings) instead of by object. If Jekyll can't write a file again that a carried record needs, the build is done again without them.
- **AI step:** its files are moved aside while Jekyll runs and put back after, and only the markdown and zips whose content changed are written. Files it no longer makes are removed.
- Builds without `-watch` are unchanged.

Adds `SpecMapManagerSignatureTest` and tests in `JekyllDriverTest`, `WatchCompleteBuildJekyllTest`, `HtmlCheckReplayTest`, `AIProcessorTest`, `WatchSessionTest` and `RebuildPagesFallbackTest`; existing tests pass. Builds on #1461.
