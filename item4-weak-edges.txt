Title: Rapido: what only links to a changed file isn't validated or rendered again

In `-rapido` and `-watch`, a profile edit validates and renders again everything that reaches the profile through any chain of references. On uz.dhp.core a short text change in the specimen profile renders about 190 files and validates about 180, because profiles target each other (adverse event -> observation -> specimen) and examples claim those profiles. Most of that work produces the same output.

### Cause

The Rapido dependency hash treats every reference as a full dependency, followed transitively: a profile's hash includes the content of every profile its `targetProfile`s point to, and of everything those depend on, and the same for Reference.reference and links in narrative. But the validator only checks that a reference target exists with the right type (the publisher's policy is CHECK_EXISTS_AND_TYPE), and a target profile only needs to exist with the right type, kind and base. Pages only link to target profiles by title and path.

### Fix

- Edges are full or weak. For a weak edge the hash holds the target's identity (key, file, url, version, name, title, base, and for a StructureDefinition its type, kind, derivation, abstract and logical target extensions, with its base chain), not its content, and doesn't go on through it.
- `ElementDefinition.type.targetProfile` and narrative links are weak for validation and rendering. `Reference.reference` is weak for validation only (a page may show the target), and only in R4+ IGs (before R4, bindings and questionnaires are References).
- Validation follows every edge, as before, when the resource can read its targets: a `resolve()` or `conformsTo(` in it or in what it depends on, in the IG or in a definition from core or a package that it is validated against (type, profiles, imposed profiles, extensions, element types), a discriminator path through a `reference`, contained or bundled resources (validated with CHECK_VALID), a MeasureReport, or no worker context.
- A page lists what only links to it by identity, so a content change there doesn't render it again.

Adds 15 tests in `RapidoDependencyAnalyserTest` and `RapidoTrackerResourcesTest`, including one where the real narrative renderer shows a referenced patient's name, so the referring resource is still rendered again; existing tests pass.
